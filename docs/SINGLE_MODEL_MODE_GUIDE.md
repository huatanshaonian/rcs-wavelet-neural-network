# 单模型测试模式使用指南

> **版本**: v1.0
> **日期**: 2026-01-06
> **用途**: 快速验证Angle-based RCS网络表达能力

---

## 🎯 功能概述

单模型测试模式允许**只使用一个或几个模型**的RCS数据进行训练，用于：
- ✅ 快速验证网络架构（训练速度提升10倍）
- ✅ 检查网络表达能力上限（单模型过拟合测试）
- ✅ 调试数据流和训练流程
- ✅ 超参数快速调优

---

| 模式 | 模型数量 | 数据点数 | 训练时间/epoch | 适用场景 |
|------|---------|---------|---------------|---------|
| 全部模型 | 200 | 4,968,600 | ~30秒 | 最终训练 |
| 单模型 | 1 | 24,843 | ~3秒 | 快速验证 |
| 3个模型 | 3 | 74,529 | ~5秒 | 小规模测试 |

**速度提升**: 约10倍（单模型 vs 全部模型）

## 🛠️ 使用方法

### GUI界面操作

1. **启动GUI**
   ```bash
   python gui.py
   ```

2. **进入Angle-based RCS标签页**

3. **启用单模型测试**
   - 在"📊 数据配置"组中
   - 勾选"单模型测试 (快速验证网络表达力)"
   - 输入模型索引（见下方示例）

4. **点击"加载数据"**
   - 系统会自动过滤数据
   - 日志中会显示过滤信息

5. **正常训练**
   - 后续流程与全模型训练完全相同

### 模型索引格式

| 输入 | 说明 | 数据量 |
|------|------|--------|
| `0` | 只使用model_001 | 1/200 (0.5%) |
| `50` | 只使用model_051 | 1/200 (0.5%) |
| `0,1,2` | 使用前3个模型 | 3/200 (1.5%) |
| `0,50,99` | 使用3个分散模型 | 3/200 (1.5%) |

**注意**: 索引从0开始（0 = model_001, 1 = model_002, ...）

## 📈 推荐实验流程

### Phase 1: 单模型过拟合测试（快速验证）

**目的**: 验证网络有足够表达能力

**配置**:
```
模型索引: 0 (或 50，选一个典型模型)
Epochs: 200
Dropout: 0.0 (关闭正则化)
Batch Size: 256
Learning Rate: 1e-4
```

**期望结果**:
- ✅ Train Loss < 0.0001（能完美记住）
- ✅ Val Loss < 0.001
- ✅ 收敛速度: 50-100 epochs

**时间**: ~10分钟（200 epochs × 3秒）

**如果失败**:
- ❌ Train Loss > 0.01 → 网络容量不足，增加隐层
- ❌ 不收敛 → 学习率问题，降低学习率

---

### Phase 2: 小规模泛化测试（中等规模）

**目的**: 测试多模型泛化能力

**配置**:
```
模型索引: 0,1,2,3,4 (5个模型)
Epochs: 200
Dropout: 0.1
Batch Size: 256
```

**期望结果**:
- ✅ Train Loss < 0.01
- ✅ Val Loss < 0.05
- ✅ 泛化gap: Val Loss / Train Loss < 5

**时间**: ~20分钟

---

### Phase 3: 全模型训练（最终训练）

**目的**: 在全部数据上训练最终模型

**配置**:
```
取消勾选"单模型测试"
Epochs: 500
Dropout: 0.1
使用子集: 可选（加速）
```

**时间**: ~4小时（500 epochs × 30秒）

## 🔍 调试技巧

### 1. 检查网络容量

```python
# 单模型训练应该能过拟合（train loss → 0）
# 如果不能 → 网络太小或有bug
```

### 2. 对比基准

| 指标 | 单模型 | 5模型 | 全部模型 |
|------|--------|-------|---------|
| Train Loss | < 0.0001 | < 0.01 | < 0.05 |
| Val Loss | < 0.001 | < 0.05 | < 0.1 |
| 泛化gap | ~1x | ~5x | ~2x |

### 3. 常见问题

**Q: 单模型都学不好？**
- A: 网络架构有问题，检查：
  - 隐层维度是否太小
  - 激活函数是否合适
  - 数据预处理是否正确

**Q: 单模型学得好，多模型不行？**
- A: 网络容量不足以泛化，尝试：
  - 增加隐层维度
  - 增加网络深度
  - 调整Dropout率

**Q: 为什么要选model_001（索引0）？**
- A: 任意选择都可以，建议：
  - 选中间模型（如model_050, 索引49）更有代表性
  - 或者选多个分散模型（如0, 50, 99）

## ⚠️ 注意事项

1. **索引范围**: 必须在 [0, N-1] 范围内（N = 模型总数）
   - 例如: 200个模型 → 索引 0-199

2. **数据一致性**: 单模型训练的模型**不能**用于全模型预测
   - 参数分布不同
   - 需要重新训练

3. **Early Stopping**: 单模型训练收敛更快
   - 建议降低patience（如20-30）
   - 避免浪费时间

4. **GPU显存**: 单模型模式显存占用更小
   - 全模型GPU预加载: ~300MB
   - 单模型GPU预加载: ~1.5MB
   - 可以增加batch size
